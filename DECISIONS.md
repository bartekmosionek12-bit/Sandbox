# Decisions

Owner decisions (Bartek, 2026-10-17) and the defaults Claude picked where the owner left a
point open. Defaults follow the rule "most conservative, fail-closed option".

## Owner decisions

| ID | Decision |
|---|---|
| D1 | PR #4 merged into `main` as the baseline (merge commit `87378e4`). Every audit hole is fixed on top of it with a regression test that fails before the fix. |
| D2 | Package renamed `sandbox_rce` -> `safeloadai`, no compatibility layer. Project moved from `SAFE_LOAD_MODEL/` to the repo root (`src/safeloadai/`). |
| D3 | Sandbox runtime: CPython on WASI under wasmtime. Pyodide dropped. Memory cap, fuel, one read-only preopen, no network, no other filesystem, plus a host-side wall-clock kill of the runner subprocess. |
| D4 | No file is deleted until the owner approves the list (asked at M8). |
| D7 | Default branch is not changed until the owner approves (asked at M8). |
| -- | Lambda layers: CLEAN only if static analysis succeeds AND emulation completes AND neither records dangerous behaviour. Any anomaly => SUSPICIOUS. No Python-version guessing. |

| D5 | strace mode kept only inside the optional deep backend; result cache kept but disabled by default until it is keyed and signed. | Cache poisoning risk (audit S10); no deletion without approval. |
| D6 | Work happens on `claude/safeloadai-audit-mnvlqm`, merged into `main` through PRs. | Keeps `main` reviewable; the old default branch is untouched. |

Real benign models from the Hugging Face corpus (M6) decide what gets added; callers will be able to pass extra exact pairs explicitly (M5). |
| C6 | Torch allowlist entries come from the globals `torch.save` emits (torch's own weights-only list), marked unverified in `allowlists.py` until M6 checks them against real checkpoints. | No torch in this environment yet. |
| C7 | Legacy `.h5` is SUSPICIOUS ("cannot analyse") until the in-sandbox HDF5 reader exists. | Fail closed; HDF5 parsing never runs on the host. |
| C8 | Evidence channel = writes to fd 3 (the read-only preopened directory), with `fd_write` implemented by the runner instead of WASI. Guest stdout/stderr are captured but never interpreted. | Python code in a WASI guest cannot call custom wasm imports, but every write goes through `fd_write`, and a directory fd has no legitimate write use. Measured: closing fd 3 inside the guest does not cut the channel. |
| C9 | The library never downloads the runtime. It uses `$SAFELOADAI_WASI_PYTHON` or `~/.cache/safeloadai/runtime/` and checks the pinned sha256. WASI tests skip when the runtime is absent, except in CI (`SAFELOADAI_REQUIRE_WASI=1` turns a missing runtime into an error). | The library itself never touches the network. Owner approved (decision card, 2026-10-17) that CI downloads the pinned runtime from GitHub Releases and checks its sha256. |
| C10 | Compiled-module cache is used only if its directory is owned by the user and not group/other-writable. | A `.cwasm` file is native code loaded without verification. |
| C11 | `time.sleep` is replaced inside the guest by a stub that records an anomaly and returns. | Blocking WASI calls ignore fuel and epochs; a waiting payload is itself a signal. The wall-clock kill stays as backstop. |
| C12 | The pickle emulator returns real objects only for pure data types (`builtins` dict/list/set/frozenset/tuple/int/float/complex/str/bytes/bytearray/bool/slice/range, `collections.OrderedDict`, `_codecs.encode`); every other global becomes a recording fake. | Anything real that the stream can call widens what a payload reaches inside the guest. |
| C13 | Lambda bytecode that fails any validity check (marshal error, `dis` error, unknown opcode, no `RESUME` prologue) is recorded as an anomaly and never executed. Unknown globals and closure cells become fakes and are recorded as anomalies ("missing stub"). | Owner's Lambda rule: any anomaly means SUSPICIOUS, never a version guess. |
| C14 | `getattr` with a dunder name, and introspection names (`__subclasses__`, `__globals__`, `type`, `_getframe`, ...) in Lambda bytecode, are anomalies; the dunder lookup returns a fake instead of the real attribute. | These are how code steps around the fakes to the real interpreter. |
| C15 | Lambda bytecode must also pass a layout check: every instruction a real opcode of the guest interpreter, followed by exactly its number of zeroed inline caches. | Measured: the Lambda in `poc/samples/evil_lambda.keras` (another CPython version) starts with `RESUME`, passed the prologue check and crashed the guest (wasm trap). |
| C16 | Final verdict = worst layer verdict. Emulation unavailable (no runtime) makes pickle, torch and Lambda files SUSPICIOUS. A Keras model whose only static finding is Lambda bytecode without sink names is deferred to emulation; anything else static stays. | Owner rules (judge escalate-only, Lambda rule, fail closed). |
| C17 | `safe_load` always forces `safe_mode=True` (Keras) and `weights_only=True` (torch), overriding caller kwargs, and unpickles with an exact-pair allowlist. A CLEAN Lambda model therefore still fails to load in Keras safe mode. | Loader enforces the policy independently of the verdict (audit S6). |
| C18 | CLI exit codes: 0 all CLEAN, 1 any MALICIOUS, 2 usage error, 3 any SUSPICIOUS. | Distinguishes "blocked as malicious" from "not confirmed clean" in CI. |
| C19 | The judge receives structured evidence only: enum fields, counts and identifier-shaped names; free text (disassembly, logs, arguments, reasons, errors) is dropped. | Audit S12; the attacker controls every free-text field. |
| C20 | Deep-mode (Docker) events are the union of streamed EVENT lines and the RESULT record; more than one RESULT line is tampering (MALICIOUS). Any detonation event is at least SUSPICIOUS. | Audit S5 and S4. |
| C21 | The Flask dashboard (`app/server.py`) still calls the removed `pipeline.analyze` and is broken until M7 turns it into a Report viewer. | Scheduled in M7; no test covers it. |
| C22 | Known limit (for LIMITATIONS): Lambda bytecode from another CPython version that is byte-identical to valid 3.12 bytecode (measured: `lambda x: x` from 3.11) passes every check and runs. Only an irregularity is detectable; Keras metadata does not record the Python version. | Owner rule forbids version guesses; this case raises no anomaly to act on. |
| C23 | `.joblib` files stay SUSPICIOUS: raw array bytes follow the pickle and `joblib.numpy_pickle.NumpyArrayWrapper` is not allowlisted. Measured: all 7 false positives in the first lab evaluation. | Supporting joblib means parsing its container; not in scope yet. |
| C24 | The root demo scripts (`test_1..4_*.py`, `test_lib.py`, `simple_evil.py`) were rewritten against the new API instead of deleted; their scenarios are covered by `tests/test_corpus.py`. Deleted in M8 after owner approval (C29). | Owner: do not delete files yet. |

The nsjail flags are UNVERIFIED (no nsjail here). No backend means SUSPICIOUS. | Deep mode runs the real loader on the real kernel; it is opt-in and can only add findings. |

## 0.3.0: bundled runtime, joblib, legacy HDF5

Owner request of 2026-10-18 (`pip install safeloadai` must be enough; joblib and legacy
Keras `.h5` supported; false positives re-measured). Defaults picked by Claude:

| ID | Default | Rationale |
|---|---|---|
| R1 | The runtime ships as its own package, `safeloadai-runtime` 0.1.0, holding the unmodified `python-3.12.0.wasm` as package data. `fetch_runtime.py` is the only code that downloads it; it checks size and sha256 and fails on a mismatch. The in-tree build backend refuses to build an sdist or wheel without a verified file and never downloads, so pip never fetches anything at install time (the sdist carries the `.wasm`). Supersedes C9. | Owner spec; one 26 MB pure-Python wheel works on every platform. |
| R2 | Resolution: `$SAFELOADAI_WASI_PYTHON` if set (and then nothing else, so a typo is not silently replaced), else `safeloadai_runtime.path()`. The hash is compared with safeloadai's own pinned copy, not the runtime package's constant. The runner child hashes the bytes it compiles once more and refuses on a mismatch. | A swapped or tampered runtime package cannot vouch for itself; the second hash closes the window between check and read at no extra cost (the runner already hashed the bytes for the compile-cache key). |
| R3 | Verified hashes are cached per process, keyed by (path, size, mtime_ns, inode, device). | Spec: keep scans fast; any rewrite of the file changes the key. |
| R4 | Integrity failure raises `RuntimeIntegrityError` out of `scan`/`safe_load`; the CLI prints it and exits 4. A missing runtime stays a SUSPICIOUS emulation layer with the reason and a pointer to `safeloadai doctor`. | Owner spec: never fall back to a verdict on a tampered runtime. |
| R5 | `wasmtime>=49.0.0,<50` (was `==49.0.0`): the major version the suite runs against; `doctor` flags anything outside it. | Patch releases of the tested major; a new major needs a test run first. |
| R6 | CI builds both wheels once, installs them into a fresh venv per job (the runtime only from the build artefact, `--no-index`), then blocks the network for the test process (Linux: network namespace; macOS: `sandbox-exec`; Windows: outbound firewall rule for the venv and base interpreters), proves the block with `tools/assert_offline.py`, and runs the suite with `SAFELOADAI_EXPECT_INSTALLED=1`, under which `conftest.py` refuses to test the source tree. `src/` is no longer on the pytest path. | Owner spec: test what users install, offline. |
| R7 | On Windows the compiled-module cache directory is trusted without a permission check. | Windows permissions are ACLs that `os.stat` does not report; the cache is under the user's profile, private by default. Without it every scan recompiles the runtime. |
| R8 | The deep-mode Docker backend still needs a source checkout (it builds its image from `docker/`); installed from a wheel it reports itself unavailable, which is SUSPICIOUS. | Unchanged behaviour, now stated; deep mode is opt-in. |
| J1 | The pickle walker is now a value-tracking machine (`static/pickle_vm.py`): inert stand-ins for every value, nothing imported or called. Streams a real unpickler rejects (stack underflow, missing memo key, missing MARK, protocol > 5, out-of-band buffers) are parse errors, so SUSPICIOUS. | Needed to read a NumpyArrayWrapper's state exactly; stricter than the old stack-shape walk (one hand-written test pickle was invalid and is fixed). |
| J2 | Frames are checked like the pure-Python unpickler: a FRAME before the current one ends, an opcode that crosses a frame end, a STOP or joblib array data before the frame end are errors. | Bytes inside a frame after STOP are skipped by real unpicklers; a sequential walk would read them. |
| J3 | joblib format, read from `joblib/numpy_pickle.py` 1.6.0: after BUILD on a `joblib.numpy_pickle.NumpyArrayWrapper` built by NEWOBJ with no arguments (or `copyreg._reconstructor(cls, object, None)`), the dtype comes from `numpy.dtype(descr, False, True)` + its BUILD state; non-object data is an optional padding byte + padding (when `numpy_array_alignment_bytes` is not None) and `prod(shape) * itemsize` bytes; object dtypes are a nested pickle read by a fresh plain unpickler. The layout code is one stdlib module (`shared/joblib_layout.py`) used by the walker, the sandbox and the loader. Unsupported layouts raise and the file is SUSPICIOUS. Supersedes C23. | Owner spec: skip by shape/dtype/order, never treat array bytes as opcodes. |
| J4 | Allowlist: `("joblib.numpy_pickle", "NumpyArrayWrapper")` only (plain data holder). No scikit-learn pair is added until a real benign file from the Hugging Face set needs it (Part D). | Owner spec: exact pairs, justified. |
| J5 | Parser differential: from the first array, the bytes are also read as a plain `pickle.load` would (same stack and memo, no array hook) until that reading fails. Its imports are scored like any import (a known sink is MALICIOUS), except that the reading stops at the first import whose top-level module is neither stdlib, nor a common ML package, nor importable here. | joblib files are pickles: a file safe under joblib's reading could run code under pickle.load. Stopping at an impossible import avoids false positives from names stitched together out of the outer memo (measured on sklearn models with object arrays). |
| J6 | Compressed joblib is decompressed on the host with the standard library codecs (lz4 with the optional `lz4` package), streaming, at most 1 GiB of output and at most 1000:1 once past 1 MiB, xz/lzma decoder memory capped at 256 MiB, exactly one stream (trailing data refused). The decompressed pickle goes to the sandbox as the artefact. | Decompression is not deserialisation; the WASI build lacks `_lzma`. Small high-ratio files are allowed because they cannot exhaust memory. |
| J7 | lz4 without the `lz4` package: SUSPICIOUS with the reason and the install hint (`safeloadai[lz4]`). | Owner spec. |
| J8 | Legacy joblib < 0.10: the `ZF` container is decompressed and walked; any `NDArrayWrapper`/`ZNDArrayWrapper` (side files) makes the file SUSPICIOUS. | Side files are other files, opened by name and read with `numpy.load(allow_pickle=True)`; one scan covers one file. |
| J9 | `safe_load` reads joblib with its own reader: the restricted `find_class` (the wrapper maps to an inert local class, so joblib is never imported), the same layout code, `numpy.frombuffer` for raw arrays, a restricted plain unpickler for object arrays, native byte order like joblib. | The loader must enforce the policy on its own; joblib's nested reader would otherwise unpickle object arrays without restriction in older versions. |
