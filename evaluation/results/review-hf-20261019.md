## The false positives, by cause

- **1 MALICIOUS, a scanner bug.** `Steenslid/ecg-ptbxl-classification/ecg_cnn_final.keras`: `compile_config.loss` names a custom loss saved as `builtins.binary_focal_loss`. `_promote_sinks` in `static/keras_static.py` treats any name in the `builtins` module as a known sink. `builtins` has no `binary_focal_loss`, so Keras cannot import it and there is nothing to run. The Hub scan reports this file clean. Fix to consider: for `builtins`, promote only names that `is_dangerous_import` flags, and leave the rest UNVERIFIABLE.
- **8 RISKY, unrecognised format.** OpenVINO `openvino_model_qint8_quantized.bin` files in seven sentence-transformers and cross-encoder repos, and `Falconsai/nsfw_image_detection/falconsai_yolov9_nsfw_model_quantized.pt`. None is a pickle or a torch zip; safeloadai refuses to vouch for a format it cannot parse. Correct behaviour for a gate, but it counts as a false positive here.
- **2 RISKY, joblib walk.** `BenjaminB/plain-sklearn/sklearn_model.joblib` (static walk failed on a `NumpyArrayWrapper` dtype) and `DineshKumar1329/Sentiment_Analysis/vectorizer_model.joblib` (walk limit reached).
- **21 UNVERIFIABLE, imports outside the allowlist.** `transformers` `training_args.bin` (4), ultralytics YOLO (2), pyannote (1), LightGBM (2), scipy sparse (1), scikit-learn classes not yet listed (3), `__main__` classes from custom pipelines (4), custom Keras layers and Keras preprocessing layers (4). Each can be accepted item by item with `--accept-unverified`. The full list of missing allowlist entries is in the run's `.md` file; none was added.
